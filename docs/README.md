# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation hub. This guide helps you navigate our standardized processes for managing cross-functional projects.

## About OctoAcme Project Management

OctoAcme follows a structured, lifecycle-based approach to project management that emphasizes customer value, iterative delivery, and clear ownership. Our core principles ensure consistent, scalable project execution:

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has named Project Manager and Product Lead roles
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

OctoAcme projects follow a five-phase lifecycle: **Initiation** (validate business needs), **Planning** (build actionable roadmap), **Execution** (deliver and monitor), **Release** (ship with confidence), and **Retrospective** (capture learnings). Risk management and stakeholder communication are woven throughout, with clear escalation paths and structured communication cadences. This approach enables teams to surface blockers early, maintain alignment across dependent teams, and embed continuous improvement into project delivery.

## Core Concepts

- **Key Artifacts**: Project Charters / One-pagers, Risk Registers, Retrospective Notes, Decision Logs, and Release Plans
- **Communication Cadence**: Weekly PM/PdM syncs, twice-weekly standups, monthly stakeholder updates, ad-hoc escalations
- **Quality Standards**: Small PRs (<= 400 lines), automated CI/CD, security scanning, test coverage, and manual QA for feature acceptance
- **Escalation Path**: Team-level → PM → Product Lead → Sponsor (with separate incident response procedures)

## Key Workflows

- **Planning**: Kickoff → Backlog creation → Estimation → Definition of Done → Risk identification → Release plan
- **Execution**: Daily standups → PR workflow (small increments, CI gates, review) → Weekly syncs → Demo/Review
- **Quality Assurance**: Unit tests → Integration tests → Security scanning → Manual QA → Smoke tests pre-release
- **Risk Management**: Identify → Assess → Mitigate → Monitor (reviewed at weekly syncs)
- **Communication**: Weekly status templates → Incident playbooks → Blameless retrospectives → Action item tracking
